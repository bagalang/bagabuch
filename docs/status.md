# Състояние (към 2026-09-08)

> Обновявай този файл когато качваш нещо съществено. `PLAN.md` не е истина
> за всеки ред.

## Готово и се ползва

- фирми, активна фирма, настройки + SAF-T реквизити
- търговски обекти и поделения, собственици, предприятия-майки
- кочани за изходящи документи (вкл. `internal`)
- сметкоплан с търсачка към SAF-T номенклатурата на НАП; при нова фирма
  (и с бутон) се зарежда двойният сметкоплан NRA_Nom_Accounts
- контрагенти + VIES (адресът се дели към SAF-T с Mistral 3B),
  стоки/услуги, мерки, основания за 0% ДДС
- Mistral API ключ по фирма (Настройки → Интеграции)
- сканиране на фактури (покупки/продажби): евтин Mistral OCR → чернова с
  редове (не запис по сметки); търсачка за наш артикул; мапинг по контрагент
- фактури по ППДДС + проформа, печат PDF/DOCX/ODT като `{номер}_invoice`, UBL, осчетоводяване с изписване;
  кредитно известие (`03`/`13`/`23`) се пише с отрицателни суми по същите сметки
- склад: WAC / FIFO / LIFO, партиди, наличност по обект
- вътрешен приемо-предавателен протокол (стоки + ДМА, без дневник)
- дневник (от пост и ръчен); отрицателен знак във формуляра и в базата
  (сторно / кредитно / аванс / корекция — същите Дт/Кт, без обръщане);
  ДДС дневници от записите + редовете на фактурата (ставки 20 / 9 / 0,
  освободени, ВОД); ППДДС клетки 01-01…01-82; файлове за НАП
  (DEKLAR/POKUPKI/PRODAGBI в Windows-1251 + ZIP)
- банки: сметки (IBAN, ГЛ + буфер), импорт на извлечения (OBB XML,
  ISO camt.053, PostBank XML, MT-940, CSV), преглед с дубликати,
  осчетоводяване и разнасяне от буфер с търсене на контрагент и сметка
- дивиденти: разпределение към действителни собственици (дял от настройките),
  снимка име/ЕГН/%, данък 5% по ЗДДФЛ, статуси
  чернова → одобрено → частично платено / платено; плащане само след одобрение
- производство: рецепти (BOM: изход + материали + фира) и поръчки;
  потвърждението изписва склада (WAC/FIFO/LIFO), заприходява продукцията
  по себестойност на материалите и прави запис Дт 611 / Кт 302
  (или складова на материала / 304), Дт 303 / Кт 611 (или 304 / 601);
  затворен месец спира confirm; завършена поръчка не се трие
- SAF-T XML експорт; номенклатурата има кодове 20 (продукция от производство)
  и 70 (запаси към производство)
- SAF-T кореспонденции на сметки (`/saft-movement-mappings`): Дт/Кт шаблони
  към тип движение за запаси / ДМА / пари; бутон за стандартни настройки
- SAF-T номенклатури на НАП (каталог, без таблица): екран `/nomenclatures`
  в менюто — движения, режими, плащания, фактури, данъци, запаси, мерки,
  области, сметки NRA
- ДМА: категории ЗКПО, амортизация (счетоводна+данъчна), преоценка,
  преместване по обект, консервация, снемане, история
- валутни курсове от ЕЦБ
- начални салда по НСС клас и аналитичност (без запис в дневника)
- счетоводни периоди: затваряне спира пост / ръчен запис / амортизация /
  confirm на протокол и на производствена поръчка
- потребители и роли (CRUD); вход с парола + JWT (jwtbaga); 2FA (otpbaga TOTP
  + резервни кодове); публична регистрация с фирма (изключва се от /admin);
  възстановяване на парола през SMTP; правата по роля се налагат върху API
  (baraba групи: super_admin / admin / accountant / viewer)
- търсачка в списъците (контрагенти, фирми, сметкоплан, стоки, дневник, …)
- икон-бутони за редакция/изтриване и сродни действия в таблиците
- тема, BG/EN
- глобални настройки (SMTP/S3 през Python sidecar :5050; S3 архивът е
  логически dump през boilaDB COPY, не tar на LSM)
- справки: оборотна ведомост (6 колони), главна книга, главна книга по
  кореспонденции (без дати/документи; водещ дебит и водещ кредит), баланс /
  ОПР / паричен поток / собствен капитал (формули в Настройки), хронологичен
  журнал (FIFO двойки), по контрагент (оборотна + хронологична); екран `/reports`;
- финансови отчети: таб Настройки → формули `+304Д` / `+702ОК` / `+304Д/401К` /
  `+@код`; стандартни формули по сметкоплана; преглед за период
  експорт PDF / Excel / ODS като таблица през reportbaga (същият път като
  печата на фактури). XLSX/ODS пишат сумите като числа (не текст); при
  български Excel/Google се вижда запетая. Периодът на справката се
  сравнява с `xml_str_lt`, не с `<` върху низове.

## Нарочно отложено (куката е там)

- отчет печалба / приходи / разходи по обект — `journal_lines.location_id`
  се пише при пост на фактура
- сторно на потвърден вътрешен протокол (складово връщане, без дневник;
  счетоводно сторно изобщо е с отрицателен знак, не с обърнати статии —
  виж `PLAN.md`)
- обект на ръчен запис и на амортизация
- SAF-T движения на стоки по обект (кодовете 20/70 са в каталога)
- работни центрове / технологични операции / QC върху производството —
  нарочно не: само рецепта + поръчка върху съществуващия склад

## Липсва (има ред в PLAN.md, няма модул)

- сторно като отделно действие върху осчетоводена фактура / ръчен запис /
  производствена поръчка (правилото е готово: нова статия с минус по същите
  сметки; бутон още няма)
- ДМА справки / складови справки
- `company_id` върху сметкоплан / ДМА / вътрешни документи / начални салда
  (фактури, дневник, стоки, контрагенти, банки, дивиденти, производство — имат)
- статуси платена / анулирана фактура в поста
