# Счетоводни отчети

Четирите съставни части на годишния финансов отчет по **СС 1** (Представяне
на финансови отчети, ДВ бр. 3/2016). Бланката е фиксирана. Счетоводителят
настройва **формули** — коя сметка, оборот или Дт/Кт кореспонденция влиза
в коя статия и с какъв знак.

Източник на бланките: `secret/СС 1 - Представяне на Финансови Отчети…html`
(локално копие на https://balans.bg/normativen-akt/nss-1).

## Къде се прави

| Какво | Къде |
|-------|------|
| Настройка на формули | Настройки на фирмата → таб **Финансови отчети** |
| Готов отчет | Справки → Баланс / ОПР / Паричен поток / Собствен капитал |
| Експорт | PDF / Excel / ODS, същият път като останалите справки |

Права: четене `accounting:read` / `report:read`; запис на формули
`accounting:write`.

## Четирите бланки

| Таб | СС 1 | `statement` | Справка `kind` |
|-----|------|-------------|----------------|
| Баланс | Приложение 1, двустранен | `balance` | `balance_sheet` |
| ОПР | Приложение 2, по икономически елементи | `pl` | `income_statement` |
| Паричен поток | СС 7 (СС 1 само препраща) — директен метод | `cashflow` | `cash_flow` |
| Собствен капитал | Приложение 4, колона „общо“ | `equity` | `equity` |

Дървото (раздел / група / статия / „общо“) **не се редактира**. Това е
каталог в кода (`backend/models/fs_nom_*.baga`), като SAF-T номенклатурите.
Нови статии по СС 1 т. 11.2–11.3 още ги няма.

Не се прави сега: ОПР по функция (Приложение 3), съкратен баланс за малки
(Приложение 6), справката за ДМА (Приложение 5), приложението към ГФО.

Сумите в прегледа и справката са **точни** (евро, две знака). Закръгляне
към хиляди по бланката още го няма. Колоната „предходна година“ е 0 —
смята се само избраният период.

## Как се пълни една статия

Всяка **листова** статия има един низ — формулата. Стойността е сбор на
токените отляво надясно. Няма скоби и приоритет (не е Excel).

Празна формула = 0. Ред с 0 за текущата (и предходната) година се крие
в смисъла на СС 1 т. 11.4 само ако няма да се показва в експорта като
празен — на екрана дървото се вижда цялото, за да се редактира.

**Сборните** редове („Общо за група I“) без собствена формула събират
сестринските `line`/`total` под същия родител. Може да се презапишат с
`@` към други статии.

### Токени

Знакът е задължителен след първия токен. Първият може без знак (= плюс).

| Токен | Какво вади | Пример |
|-------|------------|--------|
| `+304Д` | крайно салдо **дебит** (начално + обороти до `to`) | стоки |
| `-241К` | крайно салдо **кредит**, с минус | амортизация срещу ДМА |
| `+702ОК` | **оборот кредит** за периода | приходи от продажби |
| `+601ОД` | **оборот дебит** за периода | разход материали |
| `+101НК` | **начално** салдо кредит към `from` | записан капитал в началото |
| `+123НД` | начално салдо дебит | непокрита загуба |
| `+304Д/401К` | **кореспонденция** Дт 304 / Кт 401 (FIFO двойки) | покупка на стоки |
| `+50*Д/411К` | същото, `*` е префикс | каса/банка от клиенти |
| `+@bal.c.i.t` | стойността на **друга статия** от същата бланка | сбор |

Шаблон на сметка: `304` (точно или аналитично продължение `3041`),
`30*`, `50*` — същото правило като при SAF-T кореспонденциите.

Кореспонденцията ползва същите FIFO двойки като справката
**По кореспонденции** (хронологичният журнал): във всеки запис всеки
дебит се сдвоява с кредитите по по-малката сума.

### Примери

ДМА — земи и сгради, нетна балансова:

```
+201Д+202Д-242К
```

Стоки:

```
+304Д
```

Нетни приходи (ОПР):

```
+701ОК+702ОК+703ОК
```

Балансова стойност на продадените стоки/продукция:

```
+702Д/304К+701Д/303К
```

Постъпления от клиенти (паричен поток):

```
+50*Д/411К
```

Плащания към доставчици:

```
+401Д/50*К
```

Сума на актива:

```
+@bal.a+@bal.b.t+@bal.c.t+@bal.d
```

Грешна формула се отхвърля при запис (422) с кратко съобщение —
липсващ Д/К, висящ `/`, празен `@`.

## Работен ред за счетоводителя

1. Активна фирма в хедъра.
2. Настройки → **Финансови отчети**.
3. Избери бланка (Баланс / ОПР / Паричен поток / Собствен капитал).
4. **Зареди стандартни** — веднъж. Ако вече има формули, първо **Изчисти**.
5. Кликни статия вляво. Формулата е вдясно. Запази.
6. Период + **Преглед** — виждаш дали 304 е в „стоки“, а не в „материали“.
7. Готовият отчет е и в **Справки** (печат / PDF / XLSX / ODS).

Стандартните формули са скелет по националния сметкоплан (201 земи, 304
стоки, 411 клиенти, 401 доставчици, 50x пари, 70x приходи, 60x разходи).
Аналитични сметки, други 20x/60x/70x и контра-сметки се дописват ръчно.
Актив = пасив не се форсира: ако не се равнява, формулата за текущ резултат
(`+123К-123Д`) или липсваща сметка е първото място за проверка.

## Какво влиза в салдото и оборота

Същата логика като оборотната ведомост:

- **Начално** към `from` = начални салда за календарната година на `from`
  плюс оборотите от 1 януари до деня преди `from`.
- **Оборот** = редове в дневника с дата в `[from, to]`.
- **Крайно** = начално + оборот (без нетиране Дт↔Кт). Отрицателен знак в
  дневника е валиден (кредитно известие, сторно) и намалява съответния оборот.

Началните салда **не** са оборот — виж [opening-and-periods.md](opening-and-periods.md).

## Главна книга по кореспонденции

Отделна справка, не ГФО. Справки → **По кореспонденции**.

Няма дати и документи. За всяка сметка остават начално салдо, обороти и
крайно салдо. Вместо редове по документ има агрегирани Дт/Кт двойки.

Печата се **два пъти**:

- **Водещ дебит** — кореспонденциите, в които сметката е дебитирана (304 → Кт 401).
- **Водещ кредит** — кореспонденциите, в които сметката е кредитирана (304 → Дт 702).

Двойките са FIFO, както в хронологичния журнал. Финансовите отчети ползват
същия механизъм, когато формулата е от вида `+304Д/401К`.

## Другите справки (за ориентация)

Не са ГФО, но от тях се вижда дали формулите имат смисъл:

| Справка | Какво |
|---------|--------|
| Оборотна ведомост | 6 колони НД/НК/ОД/ОК/КД/КК |
| Главна книга | по сметка, с дати и документи |
| Хронологичен журнал | FIFO двойки Дт–Кт по документ |
| По контрагент | същите две, с филтър |

## API

```
GET  /v1/fs/lines?statement=balance|pl|cashflow|equity
GET  /v1/fs/formulas?statement=
PUT  /v1/fs/formulas          {statement, line_code, formula}
POST /v1/fs/formulas/defaults {statement}
POST /v1/fs/formulas/validate {formula}
POST /v1/fs/formulas/clear    {statement}
GET  /v1/reports?kind=balance_sheet|income_statement|cash_flow|equity&from=&to=
GET  /v1/reports/export?...&format=pdf|xlsx|ods
GET  /v1/reports?kind=correspondence_ledger&from=&to=
```

`defaults` отказва, ако за бланката вече има редове — първо `clear`.
